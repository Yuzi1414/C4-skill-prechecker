# 交付物预检器 Deliverable Pre-checker

提交挑战前，30 秒查出「该交什么 / 已交什么 / 缺什么 / 命名对不对 / 有没有踩红线」。
纯 Python 标准库，零第三方依赖，Windows 下直接跑。

## 一句话

> **输入**：挑战名（C1~C7 / C2A / C9 或别名）+ 文件夹路径
> **输出**：交付物清单逐条 ✅/❌ + 命名警告 + 红线警告

## 快速开始（1 分钟）

```bash
# 1) 看支持哪些挑战
python scripts/precheck.py --list

# 2) 预检某个挑战（挑战名支持别名）
python scripts/precheck.py C6 "D:\你的工作目录\C6文件夹"
python scripts/precheck.py 论文 "D:\...\C2_AI4Math"

# 3) 不确定文件夹对应哪个挑战？自动判断
python scripts/precheck.py --all "D:\...\某文件夹"
```

## 输出长什么样

```
① 该交什么   → 核心/次要交付物清单（来自注册表）
② 已交/缺失  → 逐条 ✅ / ❌ / ⚠️
③ 红线警告   → 缺核心交付物触发 missing_artifacts 红线
④ 小结       → 缺失计数 + 红线条数 + 补交建议
```

## 目录结构

```
deliverable-prechecker/
├── SKILL.md               # 技能元数据 + 触发说明（frontmatter name/description）
├── README.md              # 本文件
├── scripts/
│   └── precheck.py        # 通用引擎：读注册表 → 扫文件夹 → 匹配 → 判红线
└── references/
    └── challenges.yaml    # 数据：每个挑战交什么、命名前缀、红线（数据驱动）
```

**核心设计：引擎与数据分离。** 加新挑战不动代码，只在 `challenges.yaml` 加一条记录。

## 支持范围

已内置 8 个挑战：C1 翻译、C2 论文、C2A 提案、C9 基准、C3 群内参与、C4 技能、C6 命名权限、C7 传播（交付物待确认）。

## 常见问题

- **命名不规范但内容对，会报吗？** 会。命名规范本身是评分项，⚠️ 提醒你改。
- **子目录里的文件要带前缀吗？** 不要。命名检查只看顶层文件，避免误报。
- **目录型交付物（如 benchmark/）会被误报缺失吗？** 不会，目录名也纳入匹配。

## 局限与诚实声明

- 只做**规则核对**，不做内容质量判断（内容仍需人工复核）。
- 注册表随挑战规则更新手动维护；C7 交付物清单标注「待确认」，未臆造规则。

## 真实验证记录

本技能在开发中跑过两轮闭环验证：构造「完整样例」应全 ✅ + 零红线，「缺文件样例」应触发 ❌ + `missing_artifacts` 红线；并对真实 C9 文件夹预检，抓到 `yml_C9_测试结果.md` 独立文件缺失这个真实缺口（结果实际在 `yml_C9_benchmark/results/` 内）。
